# Second-Me 2026

[English](README.md) | 中文

本仓库是 [mindverse/Second-Me](https://github.com/mindverse/Second-Me) 的**社区分支**，不是官方版本，与 Mindverse 没有隶属关系。

上游最后一次实质更新是 2025 年 5 月。这一年里，小模型、端侧训练、Agent 记忆这几个方向都变化很大。这个分支的目标是**让 Second-Me 跟上 2026 年的业内实践**：
- 基座换成 Qwen3；
- Apple Silicon 可以直接用 MLX 训练；
- 架构上改成“事实交给记忆层检索，LoRA 只负责像你”。

下面的路线图是这个分支的主线。

> 状态：实验性。第一阶段已经完成，并做了新旧对比评测（见下文），后续阶段在路线图里按优先级排好了。

## 路线图

### 第一阶段：跟上底座（✅ 已完成）

| 业内现状（2026） | 上游现状 | 本分支做了什么 |
|---|---|---|
| 小模型换代：Qwen3、Gemma 4 这一代的 1–4B 模型，已经接近上一代 7B 的水平 | Qwen2.5，默认 0.5B | 默认 Qwen3-1.7B，可选 Qwen3-4B-Instruct-2507 |
| 端侧微调成为常规操作：Mac 上用 MLX，N 卡上用 Unsloth | 只支持 CUDA/CPU，Mac 上会误用 MPS 然后显存泄漏 | macOS arm64 自动改用 MLX LoRA，Web 界面里完成“训练 → 合并 → GGUF → 推理” |
| 记忆和人格分开：事实放外部记忆层，模型权重只负责风格 | 事实训练进 LoRA，加一条记忆就要重新训练 | 事实走检索；L2 只学风格、偏好和价值观；新增、修改、删除记忆都不用重新训练 |
| 长上下文加上下文预算 | 每个请求只有 1024 token，检索到的内容放不进去 | 8192 上下文，参考记忆有 token 预算，当前问题不会被截断 |
| 只训练回答部分、使用原生对话模板 | ChatML，所有 token 都算损失 | 原生模板，只对 assistant 计算损失，Qwen3 默认关闭思考模式 |

### 第二阶段：记忆层达到可用水平（🔜 下一步，优先级最高）

评测显示，记忆层已经能用（事实准确率 78.1%），但仍然是最大的短板：每 5 个事实还会漏掉 1 个，事实删除后会编造，检索还依赖按模型设定的阈值。

| 方向 | 业内做法 | 计划 |
|---|---|---|
| **记忆单元从“大块文本”变成“原子事实”** | Mem0 一类系统，先从对话和文档里抽取出一条条独立的事实，再分别存储 | 现在每块 4000 字，相关内容被稀释，相似度只有 0.52–0.68。改成按事实抽取，每条事实单独做 embedding |
| **混合检索加重排序** | 关键词（BM25）+ 向量检索，再用 reranker 精排，已经是 RAG 的标准做法 | 用这套组合替换现在写死 0.7 阈值的纯向量检索，阈值也不再需要按 embedding 模型手动校准 |
| **带时间的记忆和冲突处理** | Zep / Graphiti 一类时序知识图谱：同一件事有新旧两个版本时，取最新的那个，旧的标记为失效 | 解决“猫原来叫芝士，后来改名叫年糕”这类更新问题，并复用项目已有的 GraphRAG 实体图 |
| **学会说“我不知道”** | 训练时加入“检索不到就拒答”的负样本，让模型对自己知道多少有把握 | 修复事实删除后编造的问题（现在是 0/2） |
| **记忆整理与遗忘** | Agent 记忆系统会定期合并、压缩、淘汰旧记忆 | L1 摘要改成增量更新，不再每次全量重建 |

### 第三阶段：人格层更像本人（📋 中期）

| 方向 | 业内做法 | 计划 |
|---|---|---|
| 风格数据用用户自己的语言 | 用用户真实写过的文字做风格样本，不用合成的“标准答案” | 去掉上游写死的英文；从用户文档中抽取真实表达，作为风格样本 |
| 偏好优化 | DPO / SimPO / KTO 已经是小模型对齐的常规手段 | 恢复上游的 DPO 阶段（目前 Mac 上只做 SFT），并加上 MLX 的实现 |
| 合成数据质量控制 | 用裁判模型给合成数据打分，过滤掉低质量的样本 | 合成后自动打分，只保留合格的样本 |
| 适配器热切换 | llama.cpp 和 MLX 都支持运行时加载 LoRA | 记忆变化不重训；风格更新只需要换适配器，不用重新合并和转换模型 |

### 第四阶段：接入 Agent 生态（📋 中期）

| 方向 | 业内做法 | 计划 |
|---|---|---|
| MCP 成为工具接入的标准 | 主流 Agent 客户端都支持 MCP | 把“查询我的记忆”“以我的口吻回答”包装成 MCP 工具，在上游已有的 MCP 基础上扩展 |
| Agent 之间的协作协议 | A2A 等协议让不同 Agent 可以互相调用 | 替换上游已经连不上的 `app.secondme.io` 网络功能 |
| 完全本地 | 本地运行 embedding 和推理，不依赖云服务 | 默认用本地 bge-m3（MLX 或 Ollama），个人数据不出本机 |

### 第五阶段：工程效率与评测（📋 持续进行）

| 方向 | 计划 |
|---|---|
| 训练提速 | 加大批量、关掉梯度检查点（M1 Max 上峰值只用了 7.7GB），训练时间预计降到 1/3 |
| 数据合成提速 | 🧪 **已先行实现（实验性）**：数据合成并发可配置、GraphRAG 运行器支持缓存命中统计并固定模板（之前随机选模板导致缓存一直不命中）、每个阶段都有耗时统计。实际提速还没有用真实数据做过冷/热缓存对比。下一步：用非推理模型，整个流程目标从约 5 小时降到 1.5 小时 |
| 量化部署 | GGUF Q4_K_M 和 MLX 4bit，降低推理延迟（风格类问题现在中位数约 18 秒） |
| 标准评测 | 在本分支的评测之外，接入 LongMemEval、LoCoMo 这类长期记忆评测，以及 persona 一致性评测，并放进 CI |
| 验证范围 | Qwen3-4B 完整训练、CUDA 真机跑通整条流程，并把“模型变大”和“方案改进”的影响拆开来测 |

## 评测：2025 vs 2026（第一阶段的效果）

用同一份数据（10 个文档）、同样的训练参数、同一套 59 题、同一个裁判模型，比较上游原版和本分支。上游按原样运行。评测工具和方法在 [eval/](eval/)。

| 指标（开检索） | 2025 原版 | 2026 本分支 |
|---|---|---|
| 事实准确率 | 4.7% | **78.1%** |
| 记忆里没有的事不编造 | 10% | **70%** |
| 风格“像本人”（1–5） | 1.0 | **2.2** |
| 通用回答质量（1–5） | 2.2 | **3.2** |
| 盲测 A/B（新版 胜 / 负 / 平） | — | **52 / 9 / 2** |
| 不重训的记忆更新（满分 6：加入、修改、删除各 2 题） | 0 | **3.5**（加入 2/2，修改 1.5/2，删除 0/2） |
| 模板标签泄露 | 0 | 0 |
| 回答耗时中位数：事实题 / 风格题 | 2.2 秒 / 14.5 秒 | 4.3 秒 / 18.3 秒 |

**怎么解读**

- 事实来自记忆层，不是模型权重。不开检索时，本分支只能答对 12.5% 的事实题，这是有意的设计：LoRA 学的是风格，不是事实。
- 发布前那轮代码审查的修复，在**同一个训练好的模型**上，把事实准确率从 40.6% 提到了 78.1%。修复包括：参考记忆按 token 而不是按字节算预算、切块从 4000 字改成 1000 字、按 embedding 模型选择阈值。修复前，默认阈值 0.7 在 bge-m3 下什么都检索不到，原样运行只有 10.9%。
- 风格和通用质量的提升，有相当一部分来自基座模型从 0.5B 换成了 1.7B，这次评测没法把两者拆开。
- 还没解决的问题：事实删除后会编造（0/2），风格只有 2.2/5。这就是第二、三阶段要解决的。

**评测条件**：Apple M1 Max 64GB。2025 版用 Qwen2.5-0.5B 在 RTX 4070 Laptop（CUDA）上训练；2026 版用 Qwen3-1.7B 在 M1 Max 上用 MLX 训练。数据合成和裁判都是 `gpt-6.1-sol`，embedding 用 Cloudflare `@cf/baai/bge-m3`。

## 稳定性修复

这些问题在跑通完整流程时会实际遇到，本分支已经修好：

- embedding 请求分批发送（服务商每次请求有 token 上限）；出错时带上服务商返回的原因。
- L0/L1 调用大模型的超时从 30/45 秒放宽到 180 秒，适配推理类模型。
- GraphRAG 只看退出码判断成败，不再把 stderr 里的警告当成失败。
- 检索阈值按 embedding 模型自动选择（bge-m3 用 0.5，其他用 0.7，这个值是按 OpenAI 的 embedding 定的），也可以用 `L0_SIMILARITY_THRESHOLD` / `L1_SIMILARITY_THRESHOLD` 覆盖。
- 参考记忆的预算改为按 token（近似）计算，4096 个；切块从 4000 字改为 1000 字。旧数据可以调用 `POST /api/documents/reindex` 一次性重建索引。
- 训练样本超过最大长度时跳过并计数，不会让整次训练失败；默认最大长度为 4096。
- 新增、修改记忆时不再删除个人小传；embedding 日志不再记录原文。
- 原生 Linux 编译 llama.cpp 时自动使用 GPU（有 `nvcc` 用 CUDA，否则用 Vulkan），不再总是编译 CPU 版。
- MLX 训练给缓存设了上限，否则在 64GB 内存的机器上会涨到 53GB。
- graphrag 本地包实际是 zip 却以 `.tar.gz` 命名，导致安装失败，已修复。

## 快速开始（Apple Silicon）

```bash
git clone https://github.com/seasonsolt/Second-Me.git
cd Second-Me
make setup   # 需要 arm64 的 Python 3.12
make start
```

- 训练页会自动选择 MLX。
- 检索阈值会按 embedding 模型自动选择。如果用的不是 OpenAI 系列或 bge-m3，建议用 `L0_SIMILARITY_THRESHOLD` 自己校准。
- 从上游升级过来的数据，先调用 `POST /api/documents/reindex` 按新的切块大小重建索引。
- 如果 `python` 指向 x86 版本（报错 `Bad CPU type`），先把 arm64 的 Python 3.12 放到 PATH 最前面。

其余用法、Docker 部署、API 文档与上游相同，见 [docs/UPSTREAM_README.md](docs/UPSTREAM_README.md)。
